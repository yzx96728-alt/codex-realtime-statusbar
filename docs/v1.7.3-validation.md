# v1.7.3 / build11 验证记录

## 跟随与显示

现场1.7.2只有一个进程，保存坐标在当前屏幕内，但主进程记录`permission-required`。这证明不能继续把问题一概归为独立命令行误报；辅助功能恢复必须由用户在系统设置中授权，不能靠显示逻辑绕过。

本版将“浮窗是否显示”与“后台识别是否完成”分开：返回Codex时立即显示明确的等待状态，不显示旧聊天数据，不必等待识别队列。后台识别仍校验版本和当前前台应用。其他后台应用启动／退出不再反复打断Codex识别；常用运行循环模式下刷新，10秒低频检查补偿漏掉的前台激活事件。正常离开仍隐藏，不在后台扫描聊天。

增加“显示／找回小窗”菜单入口，用户主动点击时返回Codex并恢复屏内位置。自动恢复仅在窗口基本不在任何可见屏幕时调整位置，正常坐标保持。授权诊断改为读取运行中GUI进程自身上报的信任状态，绑定PID和30秒新鲜度；独立命令行探针单独标记，主进程未知时返回null，避免冒充真实GUI授权状态。

## 菜单栏CPU温度

替换弯箭头为macOS原生CPU模板图标及`57°C`式数字。深浅色由系统适配；点击仍打开原菜单。10秒后台串行采样，不增加模型调用、Hook、联网或特权辅助进程。读不到、超出可信范围或超过30秒过期时显示`—°C`，不保留假实时值。

只读AppleSMC，IOKit方法selector2，仅允许元数据命令9和读取命令5，没有任何写入、风扇控制、sudo或权限变更。80字节ABI及CPU传感器命名依据维护者发布的[SMC实现](https://github.com/exelban/stats/blob/master/SMC/smc.swift)和[传感器定义](https://github.com/exelban/stats/blob/master/Modules/Sensors/values.swift)核对；本版实现独立的原始字节传输与解码，没有引入其软件或服务。

读数口径为可用CPU传感器的最高值，非平均值或官方单一“CPU温度”。首次HID只读探测未读到CPU数据，因此未引入HID动态接口或把SoC／电池温度冒称CPU温度。当前M1 Max实测读取10个SMC传感器约53–57°C。只采用明确的M1系列键表，Intel只尝试TC0D（未实机验证）；其他系列目前显示不可用，不套用可能不同的同名键。

## 本机TCC根因证据

系统设置中首次直接核验本应用开关为off；用户认证开启后仍无法访问。只读tccd日志明确记录 `Failed to match existing code requirement`，并列出保存要求与当前程序的两组不同CDHash。已确认是签名失配，不能把蓝色开关视为权限有效，也不应继续归咎于聊天匹配或仅命令行探针。最终应用内容保持不变，已通过系统设置界面重新登记同一条授权；认证由用户完成。

## 本机验收结果

1.7.3已更新至标准Applications位置，保留1.7.2回滚备份，以下为本机验收证据；用户随后授权正式同步发布。通过系统设置移除保存旧版CDHash的授权记录、从最终1.7.3路径重新添加后，主进程实际报告授权true，命令行独立探针仍为false，证实必须区分两者。用户切换两个聊天后明确确认数据、跟随和CPU温度均正常。签名完成后没有再次替换二进制。五组Swift、7项技能安装、7项统一安装、通用构建、严格签名及包校验通过。Intel仅交叉编译。
