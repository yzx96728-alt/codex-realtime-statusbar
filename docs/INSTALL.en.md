# Codex Live Status Bar 1.7.3

This download includes the universal macOS app, the community `handoff` skill, its installer, and instructions. Monitoring reads local data and does not call a model.

1. Extract the complete ZIP and double-click `安装或升级.command` (Install or Upgrade). It verifies payload checksums and the app signature, discovers the old location/version, quits the old app normally, backs it up, stages and validates the replacement, installs/checks the skill, launches the app, and reports version, Accessibility trust and login-item status. No network, model, chat content or Codex configuration is used.
2. `/Applications` is preferred. If it is not writable, explicitly agree to use `~/Applications`; the installer never elevates privileges. Multiple old copies require your selection; an undiscovered old copy can be passed with `--existing-app /absolute/path/Old.app`. Other running copies block replacement. Backups live in `~/Library/Application Support/CodexRealtimeStatusbar/Backups`. On replacement/launch failure it attempts to restore the old app. To restore manually, quit the new app and copy the backup back to the reported original path, then check login items and Accessibility. Skill changes are independently backed up; a cancelled/duplicate skill update is explicitly reported even if app installation succeeds.
3. Choose whether to start at login: `y` enables, `n` disables, Enter preserves current state. Change this later in the menu. macOS may require approval in System Settings → General → Login Items (& Extensions). A disabled item is never silently re-enabled. The running monitor waits hidden when Codex is absent, stops its refresh timer while hidden, and resumes via workspace activation/wake events. The menu-bar ↪ remains available for settings/Quit. Deliberate Quit is respected. This is login-time standby; opening Codex cannot launch a monitor that is not running.
4. New skill installs use `~/.agents/skills/handoff`; existing `~/.codex/skills` or `$CODEX_HOME/skills` installs are updated in place. Identical required files are skipped, retaining extras. There is no declared standalone skill version: comparison is by content. Differences are treated as potential customization and require confirmation, with a complete backup under `~/.codex-handoff-backups`, outside discovery. Multiple declared handoff skills pause skill installation. The separate `安装交接技能.command` remains available for retry or skill-only installation.
5. Enable Follow current chat if needed. Valid Accessibility trust is reused; on failure the installer can open System Settings → Privacy & Security → Accessibility. You must authorize the final installed app yourself. Return to Codex to recheck; restart the same final app only if the OS still reports no trust, and remove/re-add its entry manually if necessary. No TCC reset/edit or security bypass is performed.
6. Type `$handoff` in Codex. Restart Codex if it is not discovered. Monitoring works without the skill. If macOS blocks a downloaded app/script, follow its security guidance or install manually; do not weaken system protections.

Manual installation: copy the included `skills/handoff` folder into `~/.agents/skills/`. Check for an existing skill first, including legacy locations; back it up outside skill directories before replacing it. Install only one copy. On other operating systems the instruction-only skill can also be installed manually in the host's supported skills directory; the app and `.command` installer are for macOS.

Click Token, Cache or Context for details. `↪` follows the current chat; `⌖` is pinned. Search, language, opacity and alert settings are in `⋯`.

At 65%, context turns orange with guidance on click, without a proactive popup. At 70%, it turns red and a bold “Consider preparing a handoff” hint with “Prepare handoff” / “Not now” appears only after a real normal completion and fresh eligible request. It neither flashes, sounds nor steals input focus. Each chat/tier is deduplicated across restarts; below55% re-arms. Compaction immediately invalidates old pending hints and waits for a valid baseline; cancelled tasks, duplicate broadcasts, unknown data and historical first reads do not qualify. Context is an estimate and the thresholds are heuristics, not proven optimal cost switching points. You may continue; Codex may automatically compact.

The handoff button copies an instruction and returns to its locked source chat. Paste and send it yourself. It does not send, create a chat, or generate a summary. A bare `$handoff` saves progress only. Explicitly request saving, creating/opening a new chat in the original directory and continuing for a complete handoff. The skill verifies material and receiver state before transferring ownership and preserves the source chat. If chat-management tools are missing, it provides material and an opening prompt for manual continuation. In Plan mode it plans without writing or creating chats. It has no hooks, counters or background reminder service.

Language, opacity, position, follow/pinned selection, and source bookmark are preserved on upgrade. Legacy80%/90% alert history maps to65%/70%; pending alerts are cleared and the first upgraded read establishes a baseline. Account limits are timestamped session snapshots; cache and reasoning tokens are subdivisions, not added twice.

The app targets macOS13+, includes ARM and Intel, and is ad-hoc signed without Developer ID notarization. Intel is cross-compiled, not hardware-tested. No screenshots, OCR, uploads, background models or private maintainer files are included. Verify the zip with the published `SHA256SUMS.txt`.

Source and updates: https://github.com/yzx96728-alt/codex-realtime-statusbar

Bundle ID stays `local.cc.codex-usage-monitor`. Keep the final standard installation path stable. Ad-hoc designated requirements depend on code hashes: updated binaries and path migration can require new Accessibility consent or login-item review. Stable ID/path cannot guarantee consent reuse. No Developer ID/notarization is assumed, no weaker requirement is introduced. Builders with an existing stable certificate may set `SIGNING_IDENTITY`; default remains ad-hoc. Certificate-based consent reuse has not been tested for this candidate. `PayloadSHA256.txt` checks payload integrity, not publisher identity.

The menu bar now uses a native CPU symbol and hottest-sensor temperature, refreshed every10 seconds. M1 sensors are supported; Intel TC0D is attempted without hardware validation, and other families may show unavailable. No administrator/helper/fan-control access. Use Show / recover the panel if needed. GUI trust is reported separately from the CLI probe; system consent remains required.

If an enabled Accessibility switch still fails after an ad-hoc upgrade, the saved code requirement may belong to the old version. Quit the app, remove only its old Accessibility entry, add the final installed app again, authenticate yourself, and reopen the same copy. A separate CLI probe may remain denied while the live GUI process is trusted. Check live GUI trust and actual chat following.
